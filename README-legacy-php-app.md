# Legacy PHP App — Run Guide (WSL + Apache2)

Separate run guide for `jhs_digitization-og-php-app/`.

> Important: this is **not Laravel**. It is **CodeIgniter 3** (`application/` +
> `system/` + `index.php`, `composer.json` says `codeigniter/framework`).
> There is no `artisan`, no `php artisan serve`, no `.env`. Read it as a classic
> Apache + PHP + MySQL app. The folder is **reference-only — do not edit it**
> (per `AGENTS.md`).

Reference app entry: `jhs_digitization-og-php-app/index.php:1`
DB credentials: `jhs_digitization-og-php-app/application/config/database.php:76-96`
Base URL: `jhs_digitization-og-php-app/application/config/config.php:27`
Default controller (`user` = login page): `jhs_digitization-og-php-app/application/config/routes.php:52`
Rewrite rules: `jhs_digitization-og-php-app/.htaccess:1-8`
DB dump: `jhs_digitization-og-php-app/jhs_digitization_db (1).sql`

## 0. One-click start (Windows + WSL)

Double-click `start-legacy-app.bat` at repo root. It runs
`scripts/legacy-wsl-start.sh` inside WSL with `SUDO_PASS=2106`, starts
Apache2 + MySQL, links `/var/www/html/jhs`, enables `rewrite`, ensures the
`admin` login, (re)starts `php -S localhost:8000`, and opens the browser.

```text
URL:      http://localhost:8000/  (or http://localhost/jhs/ via Apache)
Username: admin
Password: admin123
```

The `.bat` holds the sudo password in plain text (your request) — keep it
private. `scripts/ensure-legacy-admin.sh` resets `admin` to `admin123`
(`md5: 0192023a7bbd73250516f069df18b500`) without sudo if you ever need it
alone. The login form itself is intentionally **not** pre-filled — the legacy
folder is reference-only, so its `views/login.php` is left untouched.

## 2. Start services

You already did the first line — run both:

```bash

sudo service mysql start        # if this fails try: sudo service mariadb start
sudo service apache2 status

```

```bash

```

## 3. Import the database

```bash
cd "/mnt/e/fusion/recordroom/jhs_digitization-og-php-app"

# log into mysql and create DB + user matching application/config/database.php
sudo mysql -u root <<'SQL'
CREATE DATABASE IF NOT EXISTS jhs_digitization_db CHARACTER SET utf8 COLLATE utf8_general_ci;
CREATE USER IF NOT EXISTS 'jhs_user'@'127.0.0.1' IDENTIFIED BY 'Jhs12345';
CREATE USER IF NOT EXISTS 'jhs_user'@'localhost' IDENTIFIED BY 'Jhs12345';
GRANT ALL PRIVILEGES ON jhs_digitization_db.* TO 'jhs_user'@'127.0.0.1';
GRANT ALL PRIVILEGES ON jhs_digitization_db.* TO 'jhs_user'@'localhost';
FLUSH PRIVILEGES;
SQL

# import the dump (note the space + parens in the filename — keep the quotes)
mysql -u jhs_user -pJhs12345 jhs_digitization_db < "jhs_digitization_db (1).sql"

# verify
mysql -u jhs_user -pJhs12345 -e "SHOW TABLES FROM jhs_digitization_db;" | head
```

Expected tables include `file_tbl`, `issue_file_tbl`, `upload_file`, `room_tbl`,
`section_tbl`, `almirah_tbl`, `shelf_tbl`, `activity_log_tbl`, `drm_sessions`.

If import fails with `Unknown database`, re-run the `CREATE DATABASE` step above.
If login fails, change credentials in `application/config/database.php` (copy the
folder first — do not edit the canonical copy).

## 4. Option A — Run under Apache2 (port 80, recommended for parity)

Apache cannot serve `/mnt/e/...` directly without permission fixes, so symlink
into `/var/www/html`:

```bash
sudo ln -sfn "/mnt/e/fusion/recordroom/jhs_digitization-og-php-app" /var/www/html/jhs
sudo chown -R www-data:www-data /var/www/html/jhs
# writable dirs CodeIgniter needs:
sudo chmod -R 775 /var/www/html/jhs/application/cache /var/www/html/jhs/application/logs
# uploads generated by the app (create if missing):
sudo mkdir -p /var/www/html/jhs/uploads
sudo chmod -R 775 /var/www/html/jhs/uploads
sudo chown -R www-data:www-data /var/www/html/jhs/uploads

sudo a2enmod rewrite
sudo apache2ctl configtest
sudo service apache2 restart
```

Allow `.htaccess` overrides (needed for the `index.php?/$1` rewrite). Edit the
site config:

```bash
sudo nano /etc/apache2/sites-available/000-default.conf
```

Ensure the `<Directory /var/www/>` block reads:

```apache
<Directory /var/www/>
    Options Indexes FollowSymLinks
    AllowOverride All
    Require all granted
</Directory>
```

Then:

```bash
sudo apache2ctl configtest
sudo service apache2 restart
```

Open:

```text
http://localhost/jhs/
```

Login controller is the default route (`user`), so `/jhs/` lands on the login page.

If you serve it as the DocumentRoot itself instead of `/jhs`, set
`$config['base_url']` (in a **copy**, not the canonical file) to match, e.g.
`http://localhost/` or `http://localhost/jhs/`.

## 5. Option B — Quick run with PHP built-in server (no Apache)

`application/config/config.php` already has:

```php
$config['base_url'] = 'http://localhost:8000/';
```

So the fastest check is:

```bash
cd "/mnt/e/fusion/recordroom/jhs_digitization-og-php-app"
php -S localhost:8000
# then open http://localhost:8000/
```

No `mod_rewrite` / vhost needed. Use this when Apache is giving permission
trouble. Stop with `Ctrl+C`.

## 6. Verify it works

1. `http://localhost/jhs/` (Apache) or `http://localhost:8000/` (PHP server)
   shows the login page (default controller `user`).
2. Bad DB credentials give a CodeIgniter DB error page — fix
   `application/config/database.php` values.
3. 404 on every page except homepage = `mod_rewrite` / `AllowOverride All`
   missing — re-do Option A rewrite steps.
4. Blank page / session errors = `application/cache`, `application/logs` not
   writable — re-run the `chmod 775` step.
5. Check Apache errors with:

```bash
sudo tail -n 50 /var/log/apache2/error.log
tail -n 50 "/mnt/e/fusion/recordroom/jhs_digitization-og-php-app/application/logs/"*.php 2>/dev/null || echo "no CI logs yet"
```
